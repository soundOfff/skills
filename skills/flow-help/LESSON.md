# Lesson branch

## Teach before practice

1. Infer the developer's starting point from their request and existing
   conversation. State any material assumption, then begin teaching.
2. Explain one coherent concept required for the requested outcome. Connect
   what it does, why this project uses it, where it lives, and how it interacts
   with its neighboring seam.
3. Walk through one concrete repository example and point to its evidence.
   Separate project rules from general engineering practice.
4. Offer a walkthrough, the next concept, or an application exercise. Ask a
   retrieval or application question only when the developer explicitly asks
   for practice, a quiz, or an interactive lesson.
5. When the developer responds, explain the reasoning behind any correction
   before continuing.

Completion: the requested concept has been taught with current project evidence
and a concrete example. If practice was requested, one exercise is awaiting or
has been explained. Otherwise the lesson already stands as a useful answer.
