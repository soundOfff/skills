# Brainstorm branch

Use a **diverge, challenge, converge** pass around one decision. Produce a
useful first pass before asking the developer to choose.

1. Frame the outcome, constraints, non-goals, and unknowns already present in
   the request or repository.
2. Produce materially distinct viable options. Each names its mechanism,
   repository owners it can reuse, principal tradeoff, failure condition, and
   cheapest discriminating experiment. When evidence leaves one viable option,
   explain the rejected alternatives instead of inventing choices.
3. Challenge every viable option with its strongest objection and the evidence
   that would reverse the recommendation.
4. Recommend the best-supported option when the evidence establishes a winner
   or the developer asks for a recommendation. Ask about a preference only
   when a human-owned priority changes the ranking.

Completion: the developer has a grounded option set, its tradeoffs, and a
recommendation or exact unresolved priority. Its first response stands on its
own.
